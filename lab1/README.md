# Лабораторная работа № 1. Цветовые модели

**Вариант 6: CMYK ↔ RGB ↔ HLS.** Приложение ColorConverter 1.1.2.

## Цель работы

Изучить цветовые модели и реализовать интерактивное преобразование цветов
между CMYK, RGB и HLS с одновременным отображением трёх представлений.

## Средства разработки

C++17, Qt 6 Widgets, CMake 3.21 или новее. Для тестов используется Qt Test.
Для Windows выберите в Qt Creator комплект **Desktop Qt 6 / MinGW 64-bit**.
Qt, MinGW, CMake и Ninja должны быть установлены и настроены в этом комплекте.
Рекомендуется сборка в отдельной папке, которую предлагает Qt Creator.

## Возможности приложения

- Три панели CMYK, RGB, HLS и общий образец выбранного цвета.
- В каждой модели доступны точный ввод через кнопку «Ввести…», палитра и ползунки.
- Стрелки меняют RGB на 1, а CMYK/HLS — на 0,1; нажатие на дорожку ползунка
  сразу меняет его положение, затем можно продолжить перетаскивание.
- Изменение любой компоненты автоматически обновляет две другие модели и образец.
- RGB задаётся целыми числами 0–255; CMYK — процентами 0–100;
  H — градусами 0–360; L и S — процентами 0–100.
- Дробный ввод поддерживает точку и запятую. Ошибка показывается рядом с полем,
  а округление и ограничение диапазона — ненавязчивым сообщением под образцом.

При вводе CMYK/HLS значения сохраняются с точностью до одного знака после
запятой. RGB округляется до целых 8-битных каналов, третья модель пересчитывается
из этого RGB. Рассчитанные значения хранятся с большей точностью, чем показано
в полях. О потере точности появляется сообщение. CMYK рассчитывается по учебным
формулам без цветового профиля конкретного принтера.

## Структура проекта

| Путь | Назначение |
|---|---|
| `CMakeLists.txt` | Единый проект приложения, тестов и подготовки Release |
| `src/core/` | Структуры цветов и математические преобразования |
| `src/controller/` | Состояние, синхронизация моделей, сообщения об округлении |
| `src/view/` | Окно и обработка действий пользователя |
| `src/main.cpp` | Запуск приложения |
| `tests/ColorConverterTests.cpp` | Все проверки математики, контроллера и интерфейса |
| `docs/` | Пустая папка для последующего оформления документов |

Модель и контроллер отделены от интерфейса. Общие исходники используются
и приложением, и тестами.

## Открытие и запуск в Qt Creator

1. Распакуйте исходники в новую папку.
2. Выберите **Файл → Открыть файл или проект** и откройте `CMakeLists.txt`.
3. Выберите комплект **Desktop Qt 6 / MinGW 64-bit** и настройте проект.
4. Дождитесь завершения конфигурации CMake. Параметр `BUILD_TESTING` включён
   по умолчанию; оставьте его включённым, чтобы были доступны обе цели запуска.
5. В **Проекты → Запуск → Конфигурация запуска** выберите `ColorConverter`.
   Этот выбор также доступен в переключателе сборки и запуска слева внизу.
6. Нажмите **Ctrl+R**. Qt Creator соберёт и запустит приложение.

Все действия выполняются в Qt Creator. Дополнительные `.pro` и `.bat` не нужны.
Обычная сборка и запуск тестов не вызывают `windeployqt`: Qt Creator использует
среду выбранного комплекта Qt. В этой версии устранена зависимость Debug-сборки
от упаковки DLL, вызывавшая ошибку `Unable to find the platform plugin`.

## Переключение на тесты

1. В том же списке **Конфигурация запуска** выберите `ColorConverterTests`.
2. Нажмите **Ctrl+R**.
3. Посмотрите панель **Вывод приложения / Application Output**.
   После окончания тестовая программа сама завершится.
4. Чтобы вернуться к приложению, выберите `ColorConverter` и снова нажмите **Ctrl+R**.

Общий набор содержит **76 проверок преобразований и контроллера** и
**15 сценариев интерфейса**: точный ввод, округление до уже показанного значения,
очистка сообщения, ползунки, неверные значения и все три кнопки палитры.
При успешном запуске видны строки `All 76 ColorConverter checks passed.`
и `18 passed, 0 failed` — один сценарий математики, 15 сценариев интерфейса
и два служебных этапа Qt Test. Код завершения 0 означает успех.

Окна при проверке интерфейса могут кратковременно открываться и закрываться:
тест сам выполняет действия и сравнивает результаты. Ручной проверки значений
во время этого запуска не требуется. Тот же набор зарегистрирован в CTest.

## Создание Release только через Qt Creator

Конфигурация **запуска** определяет, что запускать: приложение или тесты.
Конфигурация **сборки** определяет режим: Debug или Release.

1. В **Проекты → Сборка** выберите конфигурацию **Release**.
   Если её нет, нажмите **Добавить → Release** и используйте отдельный каталог сборки.
2. В разделе **Шаги сборки / Build Steps** раскройте шаг CMake Build.
   В списке **Цели сборки / Build targets** выберите **CreateRelease**.
   Если уже выбрана цель `all`, снимите её: для упаковки достаточно `CreateRelease`.
3. Нажмите **Ctrl+B** и дождитесь успешного завершения.

Цель `CreateRelease` сначала собирает приложение. На Windows `windeployqt`
из выбранного комплекта Qt копирует нужные DLL, библиотеки MinGW и плагины
во временную папку упаковки CPack. Используется режим Release, путь к инструменту
и плагинам определяется по выбранному комплекту Qt. Перед упаковкой проверяется
наличие `platforms/qwindows.dll`. Затем CPack создаёт ZIP. Команды в терминале
вводить не нужно. Из Debug цель выдаст понятное сообщение с просьбой выбрать Release.

Результаты относительно **каталога сборки**, указанного в настройках Qt Creator:

| Путь | Содержимое |
|---|---|
| `bin/Release/ColorConverter/` | Собранный EXE для запуска через Qt Creator |
| `release/ColorConverter-1.1.2-Windows.zip` | Приложение со всеми собранными зависимостями для передачи преподавателю |
| `bin/Release/Tests/` | Отдельная папка тестов, если они были собраны |

В архив Release входят приложение, его зависимости и README; тесты и исходники
туда не включаются. Для дальнейшей разработки верните цель сборки `all`
и выберите нужную конфигурацию запуска.

Перед передачей распакуйте ZIP в новую папку и запустите `ColorConverter.exe`.
Нужно передавать весь архив, включая DLL и `platforms/qwindows.dll`.
Завершающая проверка — запуск на целевом Windows-компьютере без установленного Qt.
Если выбран MSVC, на целевом ПК может понадобиться соответствующий
Microsoft Visual C++ Redistributable; для этой работы описан комплект MinGW.

Если сборка сообщает об отсутствии `windeployqt`, проверьте выбранный комплект
Qt и его установку. Путь к инструменту определяется из этого комплекта автоматически.
Если при `CreateRelease` отсутствует `qwindows.dll`, сообщение покажет полный
путь к ожидаемому файлу. Восстановите выбранный комплект Qt MinGW через Qt
Maintenance Tool. Ошибка развёртывания останавливает упаковку; готовым считается
только ZIP после успешного завершения `CreateRelease`. Собранный EXE и обычная
сборка приложения и тестов от этого шага не зависят.

После замены старого проекта распакуйте эту версию в новую папку и откройте её
`CMakeLists.txt`. Qt Creator создаст новую папку сборки без прежних команд
развёртывания. Для обычной сборки оставьте цель `all`, для упаковки — `CreateRelease`.

Справка: [настройка запуска Qt Creator](https://doc.qt.io/qtcreator/creator-run-settings.html),
[развёртывание Qt под Windows](https://doc.qt.io/qt-6/windows-deployment.html),
[CPack](https://cmake.org/cmake/help/latest/module/CPack.html).

## Проверка и материалы для сдачи

Сборка CMake и тесты проверены на Qt 6.4.2 / Linux. Подготовка ZIP проверена
на этой системе; Windows DLL и запуск на Windows нужно проверить после сборки
вашим комплектом Qt. На других ОС имя создаваемого ZIP содержит имя этой ОС.

По заданию сдаются работающая Windows-сборка, исходники на GitHub
и сопроводительная документация. `docs/` оставлена полностью пустой по запросу.
Она есть в исходном ZIP; в Git появится после добавления документов.
